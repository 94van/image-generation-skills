# PlayForge：从极简 IP 标志到 50fps GIF 的完整教程

本教程记录本系列的制作决策，并提供可以迁移到新角色的分层流程与基础脚本。目标：十款独立的 1:1 高档极简 AI robot；细小纤细的复古打字机字体围绕底部；可爱完整的眼睛；眨眼、轻点头；有脚走动、多足爬行、无腿 Q 弹跳；不挥手、不新增肢体。

目录：1 工具与结果；2 需求迭代；3 十款设计；4 分层；5 表情；6 移动；7 镜头；8 导出；9 实操；10 检查；11 排错；12 复用。

## 1. 工具与最终结果

| 环节 | 使用方法 | 产物 |
|---|---|---|
| 灵感素材 | Cool-GIFs-For-GitHub 素材合集，可选 | 参考，不自动变成原创动画 |
| 原创造型 | 图像生成工具 + 明确的设计提示词 | 十张不同的静态图 |
| 清理与拆层 | 图像编辑、透明蒙版、人工确认关节与眼睛 | PNG 分层与 JSON rig |
| 动画 | Python + Pillow；复杂轮廓可另用 NumPy/SciPy | 逐帧画面 |
| 编码与校验 | 统一调色板、GIF 编码、逐帧解码 | 真正可播放的 GIF |

本系列历史终稿实测为每款 512×512、400 帧、20ms/帧、8 秒、标称 50fps、无限循环。播放流畅度还取决于浏览器和设备。新项目脚本默认使用相同规格。

本教程提供的是二维分层变换，不是单图自动恢复三维骨骼，不承诺真实空间转身、遮挡补全或电影镜头。随附通用脚本是为教程整理的可复用基础实现，不是丢失的历史制作脚本；仅凭终稿 GIF 不能精确重建当时所有原始层。

## 2. 需求如何一步步收敛

最初方向是桦树树皮中的“眼睛”：要完整、友善，避免密集恐怖感。随后主角改为简约 AI robot，所以机器人是本系列主体；桦树元素仅作为可选主题，不强行叠加。

静态标志完成后，用户要求真实 GIF；全图漂浮不能替代眨眼。随后强调敏捷机器人感，曾涉及打招呼；最新要求明确取消挥手，只保留可爱眨眼点头。最后扩展为移动：有脚步行、多足爬行、无腿弹跳，持续眨眼，镜头长推跟随。

复用时遵循最新要求；“不要挥手”仍生效，“只能原地”已经被后续移动要求替代。数量 n=10 表示十个独立文件，不是一张十宫格，也不是一个图换十种颜色。

## 4. 拆层：动画质量的起点

保留原始图。复制到工作目录，所有层使用相同画布尺寸，建议先在 512px 工作。准备 body.png、head.png、每只眼的透明层、每只脚的透明层、独立文字层；在 JSON 中标注头部枢轴、眼睛中心、脚关节和地面位置。

原图上的眼睛必须从脸部底层移除并补色；否则闭眼时会露出第二对眼睛。透明区域不能只补 RGB，不补 alpha：RGBA 的透明眼洞会导致闭合帧仍穿透背景。先把底层修成完整脸部，再叠眼睛。

从 RGB 图片抠角色时，避免把暖白身体和暖白背景一起删掉。陶瓷角色使用手工轮廓蒙版比统一亮度阈值可靠。黑底金色角色不能把整块背景当成身体。清除原阴影和旧文字，否则移动后出现双重阴影或残字。

拆脚时保留关节重叠区，避免分层旋转后裂缝。不要通过“切半下半身”自动声称获得精确腿骨；需要查看每张角色的真实结构。已有抬手造型可以保持静止，但不做挥手循环，不额外绘制机械臂。

## 5. 眨眼与点头

眨眼用三段动作：约 70ms 合眼、40ms 闭合、130ms 睁眼。在 20ms 帧间隔下会离散采样这些曲线。双眼通常同步，可保留极轻微时差；不要随机每帧改变眼位。敏捷感来自快速响应和柔和恢复，而非猛烈抖动。

历史 8 秒序列的建议眨眼起点：0.55、2.48、4.42、4.73、6.53 秒，其中 4.42/4.73 形成一次轻巧双眨。闭眼压缩只作用于眼睛局部，最小高度可保留约 4% 形成眼缝；更精细的角色可绘制专用闭眼弧线。

点头只变换头部与附着在头部的眼睛，绕颈部枢轴轻转约 2–4°，可配少量垂直缩放。身体、地面字体保持稳定。没有分离头部的单体角色，可用整体轻压表达回应，但要明确这是替代表情，不是真正局部点头。

## 6. 按身体结构选移动方式

### 无腿：Q 弹跳跃

一秒周期可分：0–18% 预压、18–88% 腾空、88–100% 落地恢复。预压纵向约 14%，落地约 18%，横向补偿约纵向压缩的 0.65 倍。腾空高度约画幅的 4–6%，竖向轻伸展，避免变成橡皮泥。

身体以足底/底面为缩放锚点；若以画布中心压缩，会产生悬浮。阴影在腾空时缩小变淡，落地时扩展。每次落地前后检查是否穿地。

### 双足：步行与碎步

左右腿相差半个周期，一脚支撑，一脚摆动。基础演示脚本采用绕关节正弦摆角，因此可能有滑步；高级实现应在接地阶段锁住脚在世界坐标中的位置，身体继续前移，到离地阶段再沿弧线回收脚。

短腿降低摆角和身体起伏，长腿需要更明确的膝关节与脚底轨迹。不要只旋转两条腿就把结果叫真实步态。若角色结构不足以实现自然步行，优先选小碎步或轻跳并说明。

### 多足：爬行

三足或更多脚设置错相，使任一时刻保留合理支撑点。小幅身体俯仰配合短行程，避免全部脚一起离地。不要给无脚角色新增腿来满足“爬行”。

## 7. 长推与镜头跟随

二维实现让角色保持画面中部，地面细标记反向滚动，形成跟随感；镜头尺度从约 0.96 缓慢推到 1.08。文字可以固定为画框标识，或随世界一起移动；本教程基础脚本默认固定文字，避免打字机字体晃动。

8 秒循环的折中：前 6 秒缓推，后 2 秒平滑回到起始尺度。严格单向长推不可能在固定构图中无缝回到起点；如用户要持续单向镜头，输出非循环视频或设计遮挡转场。不要把明显回退说成没有回退。

用 smoothstep：s(x)=3x²−2x³，使速度在段首段尾趋零。所有周期动作应在循环时长内完成整数周期。最后一帧取 (N−1)/fps，而不是重复首帧；检查最后到第一帧的间距是否接近相邻帧。

## 8. GIF 导出与高帧率

GIF 帧延时以 10ms 为单位。20ms 对应 50fps，适合“36fps 以上”的要求。不要把 duration=27.78ms 当成精确均匀 36fps；编码器或播放器可能取整。帧数与帧率不同：400 帧不代表 400fps。

统一从多帧采样生成约 192 色调色板，再让所有帧共用，减少颜色跳变。极简平面图一般关闭抖动更干净；陶瓷渐变可能出现色带，需要在尺寸、颜色与文件大小之间调整。GIF 不支持完整半透明，默认先合成到指定纯色背景。

写出时先在内存生成完整字节，写到 .pending，再原子替换目标；之后重新打开逐帧解码。loop=0 为无限循环；disposal=2 可避免帧残影。不要只改扩展名。播放器卡顿时可同时提供视频辅助预览，但不能省略用户要求的 GIF。

## 9. 从零运行基础演示

要求 Python 3 与 Pillow；在当前 skill 目录运行：

```bash
python -m pip install -r requirements.txt
python scripts/make_demo.py ./work/demo
python scripts/render_gif.py ./work/demo/rig.json ./work/demo/demo.gif
python scripts/validate_gif.py ./work/demo/demo.gif --frames 400 --duration-ms 20
```

演示会生成原创几何测试机器人分层，仅用于验证管线。把它替换为你自己的分层 PNG，再修改 rig.json 的路径与枢轴。详见 [rig.md](rig.md)。调整 mode 为 expression/hop/walk/crawl；walk/crawl 必须配置真实脚层才能产生脚动作。

十款角色分别存成 work/01/rig.json 到 work/10/rig.json，逐个运行渲染、检查、观看，再打包。不要将一款的眼睛坐标复制给另一款。脚本不自动抠图，也不自动生成十种风格。

## 10. 验收与交付

机器检查：文件确为 GIF；完整解码；宽高正确；400 帧；每帧 20ms；总长 8000ms；无限循环；具有不同内容的帧；计算 SHA256 和大小。脚本报告首尾平均像素差供排查，不把某个阈值当作视觉合格证。

观看检查：闭眼时没有残留原眼；点头确实在头部；原画没有多出手脚；无挥手；接地无穿透、碎片、拉伸；跟随不剧烈晃动；环形文字正确、纤细、可读；透明边缘无黑边；首尾不突然跳帧。

交付每款单独 GIF、合集、规格表和预览。教程仓库中的历史检查报告说明终稿技术参数；新的演示 GIF 只用于证明通用脚本可运行。终稿分层源图缺失时明确说明，不伪称一键逐像素重现原作。

## 11. 常见问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 还是静态 | 只有一帧或全帧重复 | 逐帧解码并检查内容差异 |
| 眼睛没闭上 | 脸层残留眼睛/透明洞 | 清除原眼并填补脸色与 alpha |
| 出现挥手 | 沿用过期动作提示 | 删除挥手层和动画轨道 |
| 脚滑 | 没有支撑锁定 | 设置接地窗口和脚底世界轨迹 |
| 跳跃像漂浮 | 无预压落地与阴影反馈 | 添加压缩、锚点、阴影联动 |
| 循环抖一下 | 非整数周期或镜头终值不闭合 | 统一时间函数，检查首尾速度 |
| 文件空或损坏 | 保存未完成就交付 | 原子写入，重新逐帧解码 |
| 文件过大 | 高分辨率、多帧、复杂渐变 | 优先降尺寸或配色；改变帧率需说明 |
