# 新 ZINE 风格收录规范

## 收录输入

用户可提供提示词、参考图或风格描述中的一种或多种。文字足够明确即可先创建 Skill；缺少图片时不要假称看过参考。要求真实垫图效果测试时必须有可访问的图像。仅有风格名称、无法推断关键形式时，询问构图或视觉特征，不擅自替用户定义体系。

## 稳定目录与独立性

- 阅读源仓库 `AGENTS.md`、根 README 及当前风格总表，沿用规范。
- 新风格放到 `styles/<英文小写连字符名称>/`，`SKILL.md` 的 name 与目录名相同，跨仓库避免重名。
- 在总表分配下一个未使用编号 `ZINE-NNN`。编号长期稳定；撤下条目时保留停用记录，不能将旧编号分配给其他风格。
- 子 Skill 可独立复制安装，所需母提示词、资源均存其自身目录，不依赖父目录中的规则或其他风格。
- 新风格不继承 ZINE-001 的上下对照、65% 留白、署名或人脸抽象等特定规则，除非新风格本身要求；不要覆盖旧 Skill。

## 每个风格需要的内容

1. `SKILL.md`：有效 name/description、触发条件、必需输入、默认参数、核心视觉约束、执行流程、输出规则、负面约束、验收。具体风格内读取必要资源，避免加载整套库。
2. `README.md`：风格编号与名称、一句话说明、题材适配、局限、安装和直接调用方式、输入输出示例、样板入口。
3. `references/master-prompt.md`：可复制母提示词，明确哪些是可变参数，哪些是风格核心规则。
4. `agents/openai.yaml`：界面名称、简介与包含 `$skill-name` 的调用语句；按当前可用 skill-creator 规范创建。
5. `examples/README.md`：样板输入/来源、参数、完整提示词链接、实际产出类型与检视记录；有图片时使用本目录内相对路径。

## 样板诚实性

优先展示用户授权用于公开仓库的示例图，或用原创题材生成风格样板。用户提供了图片不等于授权公开私人原图；授权不明时可先仅使用文字示例，或采用原创合成示例。发布前去除机器私有路径与个人信息。

区分三种状态：`文字示例`（未出图）、`合成风格样板`（原创新图）、`参考图转译示例`（实际输入图与输出图）。不以合成样板声称参考保真通过。没有出图能力时提供完整样板提示词，表中明确「待出图」，不要填入虚构图片。

生成后检查该风格核心规则、文字、署名与构图；保存最终图片和实际提示词，说明未验证的部分。具体示例题材不能成为通用 Skill 的固定主体。

## 登记与检查

- 更新总 README 的表格：编号、风格名/入口、视觉特征、题材、样板、调用方式；同步实际收录数量。
- 在画廊追加可见样板或清楚标注的文字示例。修改已有风格只更新对应条目，不改变其他规则。
- 运行可用 skill-creator 的 `quick_validate.py` 检查新增或变更的 Skill；检查元数据、相对链接、样板资源存在、直接安装的自包含性。
- 人工检查一次「按编号选择」和一次「直接调用」能否定位同一个 Skill；未知编号应返回可用项，不误路由。
- 按当前会话授权提交到目标仓库；交付总目录链接、子目录链接、样板状态与 commit。仅本地完成时如实标明。
